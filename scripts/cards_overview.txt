Parte 2: Análisis y depuración

El siguiente programa tiene 3 errores. Encuéntralos y explica por qué fallan.

```java
public class Promedio {
 public static void main(String[] args) {
 int[] notas = {4, 7, 3, 9};
 double media = calcular(notas[]);
 System.out.println("Media: " + media);
 }
 static double calcular(int[] n) {
 int suma = 0;
 for (int i = 0; i <= n.length; i++) {
 suma += n[i];
 }
 return suma;
 }
}
```

BACK:
RESPUESTA / SOLUCIÓN

Código original con los errores marcados:

```java
public class Promedio {
 public static void main(String[] args) {
 int[] notas = {4, 7, 3, 9};
 double media = calcular(notas[]);       // ← ❌ ERROR ①: sobran los corchetes al invocar
 System.out.println("Media: " + media);
 }
 static double calcular(int[] n) {
 int suma = 0;
 for (int i = 0; i <= n.length; i++) {   // ← ❌ ERROR ②: con `<=` i llega a n.length y n[n.length] no existe
 suma += n[i];
 }
 return suma;                            // ← ❌ ERROR ③: devuelve la suma, no la media
 }
}
```

1. `calcular(notas[])` → no se pasan los corchetes al invocar: debe ser `calcular(notas)`.
2. `i <= n.length` → desbordamiento: el último índice válido es length-1. Debe ser `i < n.length`.
3. `return suma;` → no devuelve la media: debe ser `return suma / (double) n.length;` para que el resultado sea 5,75 (doble división real y no entera).

Código corregido (con los 3 errores arreglados):

```java
public class Promedio {
    public static void main(String[] args) {
        int[] notas = {4, 7, 3, 9};
        double media = calcular(notas);                // ✅ ERROR ① corregido: sin corchetes
        System.out.println("Media: " + media);
    }
    static double calcular(int[] n) {
        int suma = 0;
        for (int i = 0; i < n.length; i++) {          // ✅ ERROR ② corregido: i < n.length
            suma += n[i];
        }
        return suma / (double) n.length;              // ✅ ERROR ③ corregido: devuelve la media (5,75)
    }
}
```

```java
public class Primos {

        if (n < 2) {
            return false;
        }
        for (int i = 2; i * i <= n; i++) {
            if (n % i == 0) {

        }

        }
```

=== CARD 6: ex-java-01-16 ===
FRONT:
(Examen 1 · Fundamentos de Java y control de flujo)

Parte 3: Ejercicios de programación

Explica con tus palabras la diferencia entre pasar un parámetro por valor y por referencia en Java, y entre tipos primitivos y de referencia. Pon un ejemplo en el que se aprecie la diferencia. 

BACK:
RESPUESTA / SOLUCIÓN

Java SIEMPRE pasa parámetros por valor: se copia el valor de la variable (primitivos) o la referencia del objeto (objetos/arrays).

Regla clave:
- Primitivos → se copia el VALOR → los cambios dentro del método NO afectan a la variable original.
- Objetos/arrays → se copia la REFERENCIA → modificar el CONTENIDO (p.ej. notas[0] = 5) SÍ afecta al original, pero REASIGNAR la variable (p.ej. obj = new ...) NO afecta fuera.

Tipos primitivos de Java (8):
1. `byte` — entero de 8 bits (−128 a 127)
2. `short` — entero de 16 bits (−32.768 a 32.767)
3. `int` — entero de 32 bits (el más usado)
4. `long` — entero de 64 bits (sufijo L: 10L)
5. `float` — decimal de 32 bits (sufijo f: 3.14f)
6. `double` — decimal de 64 bits (el más usado: 3.14)
7. `char` — carácter Unicode de 16 bits ('a')
8. `boolean` — lógico (true / false)

Todo lo demás (String, arrays, clases...) son tipos de REFERENCIA.

```java
public class PasarPorValor {
    public static void main(String[] args) {
        // CASO 1: PRIMITIVO → se copia el valor 10
        int num = 10;
        modificarPrimitivo(num);
        System.out.println("num = " + num);       // 10 (NO cambió)

        // CASO 2: ARRAY → se copia la referencia; apunta al MISMO
        //         array, por eso modificar el contenido SÍ afecta
        int[] notas = {1, 2, 3};
        modificarContenido(notas);
        System.out.println("notas[0] = " + notas[0]); // 5 (SÍ cambió)

        // CASO 3: ARRAY → se copia la referencia, pero reasignar
        //         solo cambia la copia local → NO afecta fuera
        int[] otro = {7, 8, 9};
        reasignar(otro);
        System.out.println("otro[0] = " + otro[0]);   // 7 (NO cambió)

        // CASO 4: OBJETO MUTABLE (StringBuilder) → se copia la
        //         referencia; modificar el objeto SÍ afecta
        StringBuilder sb = new StringBuilder("Hola");
        modificarObjeto(sb);
        System.out.println("sb = " + sb);        // Hola mundo (SÍ cambió)

        // CASO 5: STRING (INMUTABLE) → "modificarlo" crea OTRO
        //         objeto nuevo; el original nunca cambia
        String s = "Hola";
        intentarCambiarString(s);
        System.out.println("s = " + s);          // Hola (NO cambió)
    }

    // x es una COPIA del valor → x = 99 no afecta a num
    static void modificarPrimitivo(int x) {
        x = 99;
    }

    // arr apunta al MISMO array → arr[0] = 5 modifica notas
    static void modificarContenido(int[] arr) {
        arr[0] = 5;
    }

    // arr ahora apunta a un array NUEVO → otro sigue igual
    static void reasignar(int[] arr) {
        arr = new int[]{100, 200};
    }

    // sb apunta al MISMO StringBuilder → append() modifica el objeto
    static void modificarObjeto(StringBuilder sb) {
        sb.append(" mundo");
    }

    // s = ... NO modifica el String: apunta a un objeto NUEVO
    static void intentarCambiarString(String s) {
        s = s + " mundo";
    }
}
```

Resumen: se pasa SIEMPRE una copia (del valor o de la referencia). La copia de la referencia apunta al MISMO objeto, por eso mutarlo se ve fuera, pero el puntero en sí es solo una copia, por eso reasignarlo no cambia nada fuera.

Extra (trampa de examen): String es INMUTABLE, cualquier "modificación" crea un objeto NUEVO, por eso nunca cambia fuera (se comporta como un primitivo). StringBuilder SÍ es mutable: append() modifica el MISMO objeto y el cambio SÍ se refleja fuera.

Parte 4: Pregunta teórica

Explica la diferencia entre los bucles `while`, `do-while` y `for`. ¿Cuándo conviene usar cada uno? Razonar la respuesta.

BACK:
RESPUESTA / SOLUCIÓN

`while`: evalúa la condición al inicio → 0 o más iteraciones. Útil cuando no sabemos cuántas veces iteraremos y solo conocemos la condición.
`do-while`: evalúa al final → 1 o más iteraciones. Útil cuando el cuerpo debe ejecutarse como mínimo una vez (p. ej., menús).
`for`: compacto para iteraciones con contador conocido (índice + condición + incremento). Útil para recorrer arrays o rangos determinados.

RESPUESTA / SOLUCIÓN — código con los 3 errores marcados:

```java

        System.out.println(suma(nums));           // ✅ correcto: imprime el resultado de la suma

    static int suma(int[] n) {                    // ✅ método correcto
```

¿Por qué salta la excepción en esa línea?

`t += n[i]` es la línea que accede al array, y la excepción se lanza al ejecutarla. En la última vuelta del bucle i vale 5 (por el `<=`), así que el programa intenta leer `n[5]`. Pero un array de 5 elementos tiene índices válidos 0..4: `n[5]` no existe. Java detecta el índice fuera de rango en el momento del acceso y lanza `ArrayIndexOutOfBoundsException`.

```java
        System.out.println(Arrays.toString(nums)); // ✅ ERROR ② corregido: imprime [3, 1, 4, 1, 5]
    }

    static int suma(int[] n) {
        int t = 0;
        for (int i = 0; i < n.length; i++) {       // ✅ ERROR ① corregido: i < n.length (antes i <= n.length)
            t += n[i];                             // ✅ esta línea era correcta: suma el elemento
        }
        return t;
    }
}
```

Pide 8 números por teclado y guárdalos en un array. Implementa métodos para: (1) contar cuántos son pares, (2) calcular el mayor y el menor, y (3) invertir el array. Muestra el resultado. 

BACK:
RESPUESTA / SOLUCIÓN — código formateado (estilo VSCode):

```java
import java.util.Scanner;

public class ArraysUtils {
    public static void main(String[] args) {
        Scanner scanner = new Scanner(System.in);            // ✅ lector de teclado
        int[] nums = new int[8];                             // ✅ array de 8 posiciones

        for (int indice = 0; indice < nums.length; indice++) {     // ✅ lee los 8 números
            nums[indice] = scanner.nextInt();
        }

        System.out.println("Pares: " + contarPares(nums));                  // ✅ cuenta pares
        System.out.println("Mayor: " + mayor(nums) + " Menor: " + menor(nums)); // ✅ mayor y menor

        int[] invertidos = invertir(nums);                   // ✅ array invertido
        System.out.println("Invertido: " + java.util.Arrays.toString(invertidos));
    }

    // ✅ Cuenta cuántos números son pares (valor % 2 == 0)
    static int contarPares(int[] numeros) {
        int contadorPares = 0;
        for (int valor : numeros) {
            if (valor % 2 == 0) {
                contadorPares++;
            }
        }
        return contadorPares;
    }

    // ✅ Devuelve el valor más grande del array
    static int mayor(int[] numeros) {
        int maximo = numeros[0];
        for (int valor : numeros) {
            if (valor > maximo) {
                maximo = valor;
            }
        }
        return maximo;
    }

    // ✅ Devuelve el valor más pequeño del array
    static int menor(int[] numeros) {
        int minimo = numeros[0];
        for (int valor : numeros) {
            if (valor < minimo) {
                minimo = valor;
            }
        }
        return minimo;
    }

    // ✅ Crea un array NUEVO con los elementos en orden inverso
    //   (el original no se modifica: invertido[0] = último, invertido[1] = penúltimo...)
    static int[] invertir(int[] numeros) {
        int[] invertido = new int[numeros.length];
        for (int indice = 0; indice < numeros.length; indice++) {
            invertido[indice] = numeros[numeros.length - 1 - indice];
        }
        return invertido;
    }
}
```

Parte 3: Ejercicios de programación

Escribe un programa que ordene un array usando el método de la burbuja y, tras ordenarlo, busque un valor introducido por teclado mediante búsqueda binaria, mostrando su posición o -1 si no existe. 

BACK:
RESPUESTA / SOLUCIÓN

```java
import java.util.Scanner;
import java.util.Arrays;
public class OrdenaBusca {
    static void burbuja(int[] a) {
        for (int i = 0; i < a.length-1; i++) {
            for (int j = 0; j < a.length-1-i; j++) {
                if (a[j] > a[j+1]) { int t=a[j]; a[j]=a[j+1]; a[j+1]=t; }
            }
        }
    }
    static int binaria(int[] a, int valor) {
        int izq=0, der=a.length-1;
        while (izq <= der) {
            int med = (izq+der)/2;
            if (a[med]==valor) {
                return med;
            }
            if (a[med] < valor) {
                izq = med+1; else der = med-1;
            }
        }
        return -1;
    }
    public static void main(String[] args) {
        int[] arr = {9, 3, 7, 1, 5, 2, 8, 4};
        burbuja(arr);
        System.out.println(Arrays.toString(arr));
        Scanner sc = new Scanner(System.in);
        System.out.print("Buscar: ");
        System.out.println("Posición: " + binaria(arr, sc.nextInt()));
    }
}
```

Parte 4: Pregunta teórica

¿Por qué es importante que un array esté ordenado para aplicar búsqueda binaria? Explica el funcionamiento paso a paso y su complejidad en notación O grande.

BACK:
RESPUESTA / SOLUCIÓN

La búsqueda binaria divide repetidamente el intervalo de búsqueda a la mitad comparando el elemento central. Esto solo funciona si el array está ordenado, porque permite descartar la mitad izquierda o derecha con una sola comparación.
Complejidad: O(log n) en el peor caso porque se reduce a la mitad en cada paso (log2 n pasos). Es mucho más eficiente que la búsqueda lineal O(n) para datos grandes.

Implementa la búsqueda binaria de forma recursiva sobre un array ordenado de enteros. Escribe un main que busque el 19 y el 7 en {2, 5, 8, 12, 19, 25} mostrando el índice encontrado o «No encontrado».

RESPUESTA / SOLUCIÓN

```java
public class BusquedaBinaria {
    static int buscar(int[] a, int ini, int fin, int x) {
        if (ini > fin) {
            return -1;                 // caso base: no encontrado
        int medio = (ini + fin) / 2;
        }
        if (a[medio] == x) {
            return medio;          // caso base: encontrado
        if (x < a[medio]) {
            return buscar(a, ini, medio - 1, x);
        }
        }
        return buscar(a, medio + 1, fin, x);
    }
    public static void main(String[] args) {
        int[] a = {2, 5, 8, 12, 19, 25};
        int pos = buscar(a, 0, a.length - 1, 19);
        System.out.println(pos >= 0 ? "Índice: " + pos : "No encontrado");   // 4
        pos = buscar(a, 0, a.length - 1, 7);
        System.out.println(pos >= 0 ? "Índice: " + pos : "No encontrado");   // No encontrado
    }
}
Cada llamada divide el intervalo a la mitad, por lo que la complejidad es O(log n).
```

=== CARD 39: ex-java-06-15 ===
FRONT:
(Examen 6 · Recursividad y algoritmos recursivos)

Parte 4: Pregunta teórica

Explica qué es la recursión, qué papel juegan el caso base y la pila de llamadas, y en qué situaciones conviene usar recursión en lugar de iteración. ¿Qué riesgo tiene un uso incorrecto?

BACK:
RESPUESTA / SOLUCIÓN

La recursión es una técnica en la que un método se llama a sí mismo para resolver un problema dividiéndolo en versiones más pequeñas del mismo problema.
El caso base es la condición que detiene las llamadas (p. ej., n <= 1 en el factorial); sin él la recursión es infinita. Cada llamada pendiente ocupa un marco en la pila de llamadas (stack), que guarda sus parámetros y variables locales; al llegar al caso base, los marcos se desapilan devolviendo resultados.
Conviene usar recursión cuando el problema se define de forma natural recursiva (árboles, directorios, Hanoi, divide y vencerás) y cuando la versión iterativa sería mucho más compleja. La iteración es preferible cuando la profundidad puede ser grande, porque la recursión consume memoria de pila y un uso incorrecto (sin caso base o con demasiada profundidad) lanza StackOverflowError.

Explica las diferencias entre String, StringBuilder y StringBuffer (inmutabilidad, eficiencia y sincronización) y en qué situaciones usarías cada uno.

BACK:
RESPUESTA / SOLUCIÓN

String es inmutable: cualquier operación (concatenación, toUpperCase, etc.) crea un objeto nuevo. Es eficiente para valores que no cambian y para usarlo como clave en mapas.
StringBuilder es mutable y no sincronizado: modifica el mismo objeto, por lo que es la opción recomendada para concatenar muchas cadenas en un bucle (evita crear decenas de objetos intermedios).

```java
public class BusquedaBinaria {
    static int buscar(int[] a, int objetivo, int ini, int fin) {
        if (ini > fin) {
            return -1;
        }
        int medio = (ini + fin) / 2;
        if (a[medio] == objetivo) {
            return medio;
        }
        if (objetivo < a[medio]) {
            return buscar(a, objetivo, ini, medio - 1);
        }
        return buscar(a, objetivo, medio + 1, fin);
    }
    public static void main(String[] args) {
        int[] datos = {2, 5, 8, 12, 16, 23};
        System.out.println(buscar(datos, 16, 0, datos.length - 1)); // 4
        System.out.println(buscar(datos, 7, 0, datos.length - 1));  // -1
    }
}
```

```java
import java.util.ArrayDeque;
import java.util.Deque;
public class ParentesisBalanceados {
    static boolean balanceado(String expr) {
        Deque<Character> pila = new ArrayDeque<>();
        for (char c : expr.toCharArray()) {
            if (c == '(' || c == '[' || c == '{') {
                pila.push(c);
            }
            else {
                if (c == ')' || c == ']' || c == '}') {
                if (pila.isEmpty()) return false;
            }
                char apertura = pila.pop();
                if (!coinciden(apertura, c)) return false;
            }
        }
        return pila.isEmpty();
    }
    static boolean coinciden(char a, char c) {
        return (a == '(' && c == ')') || (a == '[' && c == ']') || (a == '{' && c == '}');
    }
    public static void main(String[] args) {
        System.out.println(balanceado("(a + b) * [c - {d}]")); // true
        System.out.println(balanceado("(a + b]"));             // false
    }
}
```

```java
import java.time.LocalTime;
public class Logger {
    private static volatile Logger instancia;
    private Logger() { }
    public static Logger getInstance() {
        if (instancia == null) {
            synchronized (Logger.class) {
                if (instancia == null) {
                    instancia = new Logger();
                }
            }
        }
        return instancia;
    }
    public void log(String msg) {
        System.out.println("[" + LocalTime.now() + "] " + msg);
    }
    public static void main(String[] args) {
        Logger l1 = Logger.getInstance();
        Logger l2 = Logger.getInstance();
        System.out.println(l1 == l2); // true: misma instancia
        l1.log("Iniciando");
        l2.log("Finalizando");
    }
}
```

Ventajas e inconvenientes de Singleton. ¿Cuándo lo usarías y cuándo lo evitarías?

¿Cuál es la diferencia entre `==` y `.equals()` al comparar Strings?

BACK:
RESPUESTA / SOLUCIÓN

- **`==`** compara **referencias** (si apuntan al mismo objeto en memoria).
- **`.equals()`** compara el **contenido** (si el texto es igual).

```java
String a = new String("hola");
```

¿Cuándo conviene usar `switch` y cómo se escribe?

BACK:

- `default` es opcional: se ejecuta si ningún case coincide.

Repite un bloque **mientras la condición sea verdadera** (se evalúa antes de cada iteración):

```java
int i = 0;
while (i < 5) {
    System.out.println("Vuelta " + i);
    i++;
}
```

⚠️ Si la condición nunca se cumple, el bloque **no se ejecuta ninguna vez**. Cuida el incremento para no crear un bucle infinito.

Parte 4: Bucles

¿En qué se diferencia `do...while` de `while`?

BACK:
RESPUESTA / SOLUCIÓN

El bucle **`do...while`** ejecuta el bloque **al menos una vez**, porque evalúa la condición **al final**:

```java
int i = 0;
do {
    System.out.println("Se ejecuta aunque sea una vez");
    i++;
} while (i < 5);
```

En cambio, `while` evalúa la condición **antes**, así que puede no ejecutarse nunca si la condición es falsa desde el principio.

💡 Uso típico: menús que deben mostrarse al menos una vez (por ejemplo, repetir hasta que el usuario escriba "salir").

Parte 4: Bucles

Escribe el bucle `for` y explica sus tres bloques

BACK:
RESPUESTA / SOLUCIÓN

```java
for (inicio; condición; incremento) {
    // bloque a repetir
}
```

Los tres bloques **no se ejecutan a la vez**:

1. **Inicio**: justo antes de comenzar el bucle (una sola vez).
2. **Condición**: antes de cada iteración — si es falsa, se sale.
3. **Incremento**: después de cada ciclo.

```java
for (int i = 0; i < 10; i++) {
    System.out.println(i);
}
```

💡 El `for` es el bucle más usado en Java, sobre todo para **recorrer arrays**:

```java
int[] nums = {10, 20, 30};
for (int i = 0; i < nums.length; i++) {
    System.out.println(nums[i]);
}
```

Parte 4: Bucles

¿Para qué sirven `break` y `continue` en los bucles?

BACK:
RESPUESTA / SOLUCIÓN

- **`break`**: **sale del bucle** inmediatamente.
- **`continue`**: **salta a la siguiente iteración** (ignora el resto del bloque actual).

```java
for (int i = 0; i < 10; i++) {
    if (i == 3) continue;   // se salta el 3
    if (i == 7) break;      // termina en el 7
    System.out.println(i);  // 0,1,2,4,5,6
}
```

⚠️ `break` también se usa en `switch`. En bucles anidados, `break` solo rompe el bucle **más interno**.

Parte 4: Bucles

¿Dónde vive la variable declarada en la cabecera de un `for`?

BACK:
RESPUESTA / SOLUCIÓN

**Solo dentro del bucle** (ámbito de bloque): al terminar, deja de existir.

```java
for (int i = 0; i < 10; i++) {
    System.out.println(i);
}
System.out.println(i);   // ❌ ERROR: 'i' no existe fuera del bucle
```

- A diferencia de JavaScript (`var` "se escapa" del bucle), en Java la variable de `for` tiene **ámbito de bloque**.
- Si necesitas el valor tras el bucle, declárala antes:

```java
int i;
for (i = 0; i < 10; i++) { }
System.out.println(i);   // ✅ 10
```
